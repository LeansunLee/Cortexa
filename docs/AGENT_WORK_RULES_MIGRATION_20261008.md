# Agent 工作规则统一（2026-10-08）

## 字段与执行逻辑

编辑器统一使用「工作规则」，API 和 `t_agents` 统一使用 `work_rules TEXT NULL`。
内容包括执行步骤、数据核实、协作方式、交付标准、工作边界与确认要求。
普通对话、目标执行、协作、Agent 测试、会议和记忆提取统一读取此字段；
复制 Agent 和新建版本快照也只写入此字段。
该字段是 Agent 提示词配置，不授予资源权限，也不会绕过平台或空间协作策略。
职责仍用于协作候选发现，工作规则用于指导候选发现后的执行决策。

## 历史数据迁移

执行 `migrations/merge_agent_work_rules.sql`：

- 原 `behavior` 与 `boundaries` 合并为 `work_rules`，删除两个旧列。
- 两项均非空时，按「执行方式」「工作边界」保留原文；仅一项时保留该项。
- 空白值归一为 NULL，完全相同的两项只保留一份。
- `t_agent_versions.snapshot` 同步改为单一 `work_rules` 键，保留其他配置、版本号和发布状态。
- 迁移采用事务和表锁；识别异常或部分迁移状态会回滚；完成后可重复执行。
- API 对旧请求字段提供输入归一兼容，响应及 API 文档只提供 `work_rules`。
  请求显式包含 `work_rules` 时以该值为准，包括显式清空。

部署前暂停服务，备份 `t_agents` 和 `t_agent_versions` 的表结构及数据，再迁移和部署。
回退需要恢复旧代码以及备份中的旧列、数据与版本快照，不能仅回退代码。
迁移不自动为 Peter 或其他 Agent 增添业务提示词。

原 alpha 基线文档中的 `behavior` / `boundaries` 为历史描述，以本变更为准。
