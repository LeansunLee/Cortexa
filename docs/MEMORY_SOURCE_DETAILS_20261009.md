# 记忆来源详情修复（2026-10-09）

## 原因

Memory Adapter 原来保留 `memory_id`，但 Runtime Progress 的来源白名单没有这个字段；UI 因而只收到 `type: memory`，显示“参考来源”，无法定位详情。

## 修改

- Memory 来源保留标识和简短主题标签，不将记忆正文复制到聊天元数据。
- 点击来源按需请求 `GET /api/conversations/{conv_id}/memory-sources/{memory_id}`，展示当前正文、状态、置信度、更新时间及可访问的独立来源依据。
- 检查对话所有权、对话 Agent 使用权限、本次对话召回记录和记忆所属 Agent 使用权限。来源依据逐项使用现有 `visible_evidence` 权限过滤；无需记忆管理权限。
- 撤回、归档、清除、来源待审查及未经批准的高风险记忆不会显示正文；响应禁止缓存。
- 历史执行步骤可由同一 Goal 的持久快照恢复记忆 ID，仅在 action ID 和记忆数量精确一致时恢复；不修改数据库历史记录，不按名称猜测来源。
- 未保存标识且无法可靠恢复的旧来源明确说明原因。加载失败提供重试；切换来源时清除旧内容，避免异步响应串位。

## 验证

- 51 项后端测试通过，包含实际临时 PostgreSQL 权限隔离验证，无生产数据库写入。
- 浏览器验证正文、来源依据、重试、撤回提示、无标识旧来源、HTML 安全转义。
- 前端构建通过。

无需 Schema 修改或 Migration。
