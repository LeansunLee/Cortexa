# Proxy 协作等待超时修复（2026-10-08）

## 实际故障

销售部的子任务已完整投影为 `delegated_task`。外部数据分析服务在 17:14:58 接受任务，
Cortexa 在 17:16:53 中断等待；外部服务继续执行，并于 17:19:06 完成 10,338 字报告。
Proxy 配置允许等待 1,000 秒，但运行时描述符与子任务分配均固定限制为 120 秒。

## 修复

- 协作描述符、Proxy 子任务分配和 HTTP 等待时间使用同一配置的 `timeout_ms`。
- 始终受共享 Goal 剩余时间与收尾预留限制；不关闭预算或无限等待。
- SSE `start` 的远端会话标识保存到私有执行快照，便于后续只读核实，
  该事件不作为执行进度直接推送给 UI。
- 事件回调支持同步和异步函数，开始事件在等待后续输出前完成检查点保存。
- 真正连接中断时给出明确说明，不把未知执行重新派发。
- 未修改表结构。现有已完成报告通过只读结果接口严格匹配原始任务后恢复汇总，未重跑外部请求。

## 验证

回归配置等待 1,000 秒、共享任务预算 600 秒的路径，验证 HTTP/子任务分配不再被截为 120 秒，
SSE 开始标识有检查点，原有决策暂停与续接、拒绝和未知结果保护保持有效。
