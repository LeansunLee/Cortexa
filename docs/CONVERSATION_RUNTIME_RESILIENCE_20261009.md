# 对话协作与工具调用整改（2026-10-09）

针对 `CONVERSATION_COLLABORATION_AUDIT_20261009.md` 的四项剩余问题实施整改。没有新增表、字段或执行生产 Migration。

## Changed

### 1. Proxy执行入口统一

- 修复普通入口 `UserQuestionPause` 条件import造成的异常处理崩溃。
- 普通执行、普通问答续接及Goal使用相同任务终态和输出契约校验：明确失败不能记为成功，异步运行确认不能冒充完成。
- 取消普通入口异常循环重发；保留旧retry配置兼容，但不再据此重复派发。配置UI移除无效重试次数，并说明核实策略。
- 普通执行和续接也限制响应大小，使用已有有界SSE解析；为单次传输加入整体时间上限，不能被持续心跳无限延长。UI等待设置与1000秒上限一致。
- 超时、连接故障、5xx及不完整结果保留结果未知；HTTP明确拒绝与Agent明确失败分别处理。

### 2. 原会话恢复

- 新增 `POST /api/conversations/{conv_id}/goals/{goal_id}/reconcile`。先检查对话所有权和目标Agent权限，只GET原会话结果，不POST原任务。
- 核对契约签名、session、任务/回答全文、可得的request ID，以及问答续接时的原问题身份；校验输出契约和报告大小。
- 恢复observations、原fingerprint缓存、协作记录及审计状态，保留原预算与已完成步骤。CAS确保同一个Goal恢复只能成功一次。
- 覆盖首次协作中断及主Agent提问后协作者中断；现有决策卡恢复改用这一通用链路。
- 普通Proxy执行也捕获会话身份；有身份的未知结果展示恢复卡，普通Proxy问答续接同样支持只读核实。普通恢复通过对话行锁和claim防重复续接。
- UI增加“检查原会话并继续”；恢复不新建用户任务、不清空未发送草稿，不误显示无检查点的恢复能力。

### 3. 后台生命周期与停止

- Goal首次执行复用有预算、权限监控的后台worker；HTTP观察者关闭不取消任务。producer在交付响应时创建，未连接消费者时仍能完成，队列有界。
- UI轮询已接受任务状态，重新打开页面后能看到后台执行及完成结果。
- 新增 `POST .../goals/{goal_id}/stop`。所有权检查后发送独立停止信号，取消本地worker；跨worker通过私有文件信号检测。
- 主动停止保留检查点；已开始的外部行动仍需核实，不能借停止重置预算或盲目重发。
- 使用私有heartbeat标识进程中断，避免无限duration配置令崩溃任务永久显示运行中；没有修改数据库结构。

### 4. 完成验收

- Goal及协作LLM通过 `complete_task` 声明最终答复、任务条件、实际observation IDs、未决项及本轮拒绝对象。
- 确定性检查来源存在、类型/状态匹配、直接政策证据，以及偏好引用是否来自本轮用户原文。
- 查无结果可以作为lookup的负证据，但不能冒充取得了业务事实。明确拒绝按逐Agent核对，不再只看整个拒绝名单是否为空。
- 未提交验收或未满足条件时，预算内一次纠正，随后使用现有ask_user暂停等待；用户明确接受缺失条件可交付草案。预算收尾允许标明缺失的部分结果。
- 需求识别仍由模型承担；新增结构化检查验证实际来源与声明，不宣称能形式化证明所有自然语言业务结论。
