# 自建 SearXNG

## 部署

开发服务器：47.97.82.200。SearXNG 独立部署在 `/opt/searxng`，使用自己的 Python 3.12 venv 和 `searxng` 系统账号。服务为 `searxng.service`，监听 `127.0.0.1:8888`，不开放公网端口。

源码来自 https://github.com/searxng/searxng ，部署版本固定到提交 `3fdc6d753a339b5f4a7dc5842c94c0d8324726f1`。依赖使用该提交的 requirements.txt，额外安装 gunicorn 和 pysqlite3-binary；后者仅供该服务使用，解决 CentOS 7 自带 SQLite 过旧的问题。启动适配文件见 `deploy/searxng/searxng_app.py`。

配置：`/etc/searxng/settings.yml`（随机 secret_key，root:searxng，640），缓存目录 `/var/lib/searxng`。配置示例见 `deploy/searxng/settings.example.yml`。无需 PostgreSQL 迁移，不改动业务数据库表结构。

## 应用接入

在 `/opt/agentdevstu/.env` 中设置：

```dotenv
WEB_SEARCH_PROVIDER=searxng
SEARXNG_URL=http://127.0.0.1:8888
```

不需要搜索 API Key。后端调用 `GET /search?q=...&format=json&language=zh-CN&categories=general`，统一转换为现有的网页标题、URL、摘要和搜索时间。

工具仍需在 Agent 的「工具与数据」中开启并保存发布。对话、协作、会议和 Agent 测试共享现有工具接入。平台保留三次查询预算、参数校验、响应体和超时限制；上游全部失败时返回错误，不假装没有搜索结果。

## 上游引擎

启用 360search、bing（中国站）、yandex。必应有时返回相关性较低的内容，权重调低；结果仍需模型和用户核对。百度、搜狗出现验证码/引擎错误，DuckDuckGo、Brave、Yahoo、Wikipedia 出现连接超时，已从当前配置移除。不会自动绕过验证码。

实测“Python 官方文档”返回 docs.python.org；“奔达 摩托车 官网”返回 bendamotor.cn，约 2.5 秒；“奔达 黑旗600 参数”包含车型页面。搜索引擎有波动和限流，自建免费软件不代表永久可用或结果总是准确。

## 运维

```bash
systemctl status searxng agentdevstu
journalctl -u searxng -n 50 --no-pager
curl --get 'http://127.0.0.1:8888/search' --data-urlencode 'q=Python 官方文档' --data 'format=json'
```

SearXNG 修改配置后重启 `searxng`；修改应用 `.env` 后重启 `agentdevstu`。配置状态接口仅表示已配置，不等于实时上游健康检查。

升级前备份 `/etc/searxng` 和当前源码提交，使用独立 venv 验证再替换。回退时恢复 `.env` 的原搜索 provider 并重启应用，或停止 `searxng` 服务。

## 上线验收结果

已切换应用默认 provider 为 searxng。真实模型调用 web_search 后收到 5 个网页来源，最终回答引用 `https://www.bendamotor.cn/`，未出现工具调用标记泄漏。25 项搜索/流式/检索相关测试通过；应用页面返回 200，匿名配置接口仍返回 401；两个 systemd 服务均 active，SearXNG 设置为开机启动。
