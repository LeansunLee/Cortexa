# Proxy 输入映射与拒绝恢复（2026-10-08）

## 故障与配置修正

数据分析部门原输入 Schema 要求 `requirement`，请求映射为 `prompt <- $.input`。
目标协作按 Schema 投影只生成 `requirement`，最终发送 `prompt: null`。
外部接口返回 HTTP 422，校验错误为 `body.prompt` 必须是字符串。

已将该 Agent 的输入契约统一为 `input`，沿用原有 `prompt <- $.input` 映射，
与普通对话的自动上下文整理输出一致，保留其余字段；发布了新的 Agent 配置版本。
这是具体 Agent 配置修正，Runtime 不硬编码部门名称或业务字段。

## 通用防护与恢复

- 任务协作 Proxy 的请求映射引用字段必须在输入 Schema 中声明，保存/发布及执行前校验。
- 明确的 HTTP 请求拒绝（400/401/403/404/405/413/415/422/429）单独记录为 `REJECTED`，
  保存状态码并暂停为 `proxy_request_rejected`；不会盲目重试或暴露远端错误正文。
- 用户修正配置后可以显式续跑；恢复前必须核验保存的拒绝记录，已消耗预算保持不变。
- 同批次尚未开始的工具调用补上「未执行」记录，防止续跑时向模型提交不完整的工具调用序列。
- 超时、取消和服务器错误仍保留结果未知的保护，禁止自动重试。

本次旧任务仅在日志与保存的 `prompt: null` 请求均确认 422 后才重新归类为可继续。

超时/取消/500 禁止重试、请求映射校验及原有输入投影行为。
