# AgentDevStu 产品设计说明书

版本：2026-09-18 代码盘点与产品设计基线

适用范围：当前本地 Web 平台实现、既有产品/UI 规范、下一阶段需求收口。历史版本标识仍为 alpha v1.0.2609050000，本文不另行宣布正式发版。

## 1. 文档口径与总体判断

本文面向产品负责人、开发者、测试和运维人员，说明系统为谁服务、业务如何闭环、各模块如何协作、哪些能力已经存在，以及哪些设计仍需确认或实现。依据包括后端 API 与服务代码、ORM 模型、前端页面与组件、测试、2026-09-16 项目及知识库基线、全站 UI 规范和历史 alpha 文档。

当前产品已经从早期 LangGraph 多智能体实验，发展为**企业 AI 智能体协作与工作闭环平台**。核心价值是把企业知识、业务数据和专业 Agent 接到员工日常工作中，并把讨论结果转成有负责人、交付物和验收过程的正式工作。

目前可成立的主链路是：配置与发布 Agent → 授权使用 → 对话/协作/会议 → 形成工作候选 → 人工确认分派 → 真人执行 → 提交验收 → 成果沉淀。Agent 自动执行工作尚未接入；工作流与规则管理不能作为完整交付能力承诺。

## 2. 产品目标与用户

### 2.1 解决的问题

1. 企业知识分散在文件中，员工难以定位答案和核实来源。
2. 通用模型缺少企业数据和岗位职责，回答难以直接用于决策。
3. 多人、多 Agent 讨论产生结论后，缺少负责人、交付标准和验收。
4. Agent 配置、使用授权、知识维护和运行消耗缺少统一管理。
5. 有价值的工作成果没有转成可复用的知识和记忆。

### 2.2 目标用户与职责

| 用户 | 主要诉求 | 高频入口 |
| --- | --- | --- |
| 普通员工 | 找到可用 Agent，查询资料和业务数据，执行工作 | 我的 Agent、对话、工作、知识库 |
| 业务负责人/验收人 | 汇总观点，确认行动项，分派与验收 | 会议、工作详情、组织职责 |
| Agent 开发者 | 定义角色、模型、接口和资源，测试与迭代 | Agent 配置、资源、测试 |
| Agent 运维人员 | 维护获授权 Agent 的知识、工具、数据和记忆 | Agent 运维 |
| 空间管理员 | 管理成员、资源、权限，监督空间工作 | 工作空间、用户与权限、组织管理 |
| 系统管理员 | 管理账号、角色、供应商、审计和全局用量 | 用户与权限、系统配置、模型用量 |

组织岗位和权限角色是两套概念：部门负责人可能被推荐为工作负责人，但不能因此自动获得系统管理权限。

### 2.3 产品范围

当前重点是企业内部、以 Web 为主要入口的知识协作和工作执行。移动端体现为窄屏适配，不代表已交付独立移动 App。

当前不承诺完整 BPM/ERP 替代、无人监督的 Agent 执行、统一定时调度、完整企业 SSO、费用结算系统，以及所有检索场景统一向量化。相关模型或配置入口只是基础。

下列为下一期建议建立的指标，不是当前实测数据。

| --- | --- | --- |

| 可信回答 | 正确率、有效来源覆盖率、无依据断言比例 | 固定业务题库和人工复核 |
| 工作闭环 | 候选确认率、按期完成率、退回率、流转时间 | Work 状态与活动记录 |

~~~mermaid

    K[知识 / 数据 / 工具 / 记忆] --> A
~~~

## 4. 身份、权限与工作空间

### 4.1 授权模型

实际授权由“登录用户 + 系统权限 + 当前空间成员关系 + 空间角色 + 资源授权 + 数据所有权”共同决定。前端菜单与路由守卫负责引导，后端是最终授权依据。

系统权限包括用户、角色、空间创建、配置、审计和外部身份管理。空间权限包括空间/成员管理，Agent 的查看、创建、编辑、删除、发布、使用、运维，以及知识、数据、工具、工作流、会议和记忆。

内置角色包括用户管理员、空间管理员、Agent 开发者、普通使用者，超级管理员作为特殊身份处理。Agent 开发者默认权限并不包含独立发布权限，不能把“能编辑”直接等同“能发布”。

### 4.2 隔离规则

- Agent 配置管理、草稿测试、发布和运行是不同动作。
- 运行 Agent 同时检查空间、成员、使用权限、具体授权和可用状态。
- 会话、记忆和会议有用户所有权，管理身份不自动获得他人全部私有正文。
- 普通成员按参与关系查看工作，空间管理者可查看空间范围；工作来源不能绕过原会话权限。
- 资源绑定、文档推送和负责人选择必须校验空间归属。
- 账号停用、会话失效和授权撤销需覆盖进行中的 SSE。
- 上传采用受保护文件访问机制，不能仅依赖不可猜测的地址。

### 4.3 登录与空间体验

本地登录使用 Cookie 会话，需要首次改密的账号进入改密页。未登录进入登录页，无权路由返回允许入口。切换账号或空间时清理标签和页面状态，防止旧空间表单、会话或列表残留。

外部身份提供商、身份映射有模型及管理接口，完整 SSO 协议、回调和企业账号生命周期联动仍需单独交付与验收。

## 5. 组织、岗位与推荐

已实现部门/团队层级、负责人、成员岗位、职责、职责标签和覆盖范围。组织信息服务于业务协作，不替代权限角色。

负责人推荐结合职责匹配、历史完成记录和工作负载等规则产生候选，供用户选择；不是自动派单。创建前仍检查有效成员、当前空间及负责人与验收人分离。

建议后续展示推荐理由，保留推荐结果与实际选择，评估匹配质量。跨部门协作不应隐式扩大私有数据范围。

## 6. Agent 设计

### 6.1 配置模型

| 配置 | 内容与目的 |
| --- | --- |
| 基础 | 名称、描述、头像、类型、空间，帮助识别用途 |
| Persona | 人格和表达风格 |
| Role | 岗位、职责、主要任务 |
| Boundary | 能力与业务承诺边界 |
| Behavior | 方法、步骤和输出方式 |
| 模型 | 供应商、模型、相关参数 |
| 输入输出 | Schema、参数说明和结果约定 |
| 资源 | 知识库、数据能力、工具、记忆、协作配置 |
| 版本发布 | 配置快照、版本说明和发布记录 |

### 6.2 两种运行类型

LLM Agent 根据配置构建提示词，按场景注入知识、记忆、组织及工具，通过 LangChain 调用模型，流式使用 astream。

Proxy Agent 调用外部 HTTP 接口，配置方法、地址、头部、字段映射、参数解析、超时与结果处理。平台内上下文可用于解析参数，但外发应符合配置和 Schema，不应默认发送完整私有历史。

类型切换显示适用字段，并保留可恢复的另一类型配置。错误区分参数不足、接口失败、超时和模型失败。

### 6.3 生命周期与版本

已有创建、配置、测试、版本快照和发布。尚需明确：编辑已发布 Agent 何时影响使用；历史会话续聊采用旧配置还是新版本；知识/数据绑定是否冻结。

建议所有运行入口记录实际版本与资源摘要，发布切换影响后续运行，历史会话升级有明确入口。目前不能宣称所有入口都已统一采用不可变快照。

### 6.4 验收重点

获授权用户可找到并运行 Agent；跨空间/未授权访问被拒；测试保留真实失败；Proxy 参数不合 Schema 时不外发；工具或模型失败不生成伪造成功结果；一次运行可追踪实际配置。

## 7. 对话与协作

### 7.1 对话流程

选择 Agent → 新建/打开会话 → 输入与附件 → 查看检索/工具过程 → 流式回答 → 查看来源与完整协作输出 → 重生成、保存记忆或提取工作。

已实现会话列表、搜索、重命名、删除消息、重生成、附件、SSE、表格、来源、调试面板和部分中断恢复。消息历史目前整批加载，大会话存在传输和渲染压力。

### 7.2 可信状态

区分检索中、工具完成、回答中、中断和持久化完成。搜索已结束后不能因答案仍在生成而一直旋转。失败保留用户输入和可理解的重试入口，避免留下未发送的乐观消息。

来源区分企业知识、业务数据和公开网页。工具失败、未执行、结果截断必须可见；不能用历史回答或模型猜测代替实时数据。调试信息需要脱敏。

### 7.3 协作草稿与调用

用户用 @ 选择协作 Agent，各自拥有独立任务、输入和依赖，主输入不能自动复制到空任务。输入预览帮助确认外发内容。已实现输入快照、依赖输出、过程/结果卡片和超时失败记录。

默认每次最多 3 个 Agent、深度 2、超时 120 秒，实际配置可覆盖。卡片应能展开完整输出，不仅展示摘要。

建议统一取消、重试、依赖失败和重复发送语义；跨 Agent 输入保留最小必要上下文；失败与用量链关联。消息分页采用稳定排序和游标，并保留历史定位、来源与协作信息。

## 8. 多 Agent 会议

会议包含目的、参与者、主持、轮次、附件、发言、总结、冲突和待办相关处理。主流程为明确目标 → 选择参与者 → 添加材料 → 多轮讨论 → 查看结论、分歧与行动项。

会议待办目前不等于正式 Work，存在提取代码不意味着已经自动分派执行。

建议转工作时展示目标、负责人、截止时间、验收要求及来源摘要，由用户审阅确认，并保留幂等标记。共享工作只携带必要业务摘要，不能泄露私有会议正文。

## 9. 工作 Work 与真人闭环

### 9.1 字段与创建

工作包含标题/目标、说明、交付要求、负责人类型与对象、验收人、P0–P3 优先级、带时区截止时间、来源类别/摘要、状态、活动和交付物。

负责人和验收人必须为当前空间有效成员，真人负责人不能同时验收自己。对话提取产生候选，接受后才形成 Work；模型提取不等于派单。

### 9.2 当前状态机

~~~mermaid
stateDiagram-v2
    [*] --> todo: 分派给真人
    todo --> in_progress: 负责人开始
    in_progress --> review: 提交交付物
    review --> completed: 验收通过
    review --> in_progress: 填写原因后退回
    todo --> cancelled: 取消
    in_progress --> cancelled: 取消
    review --> cancelled: 取消
    [*] --> pending: 分派给 Agent
    pending --> cancelled: 取消
~~~

模型/权限逻辑还包含 draft、rejected 等状态，不能据此推断都有独立完整界面。Agent 分派保持 pending，自动执行器尚未接入。

### 9.3 动作权限与一致性

| 动作 | 主要规则 |
| --- | --- |
| 查看 | 普通成员看创建/负责/验收的工作，空间管理者看空间范围 |
| 编辑 | 创建人或空间管理者，在允许编辑的早期状态 |
| 开始 | 真人负责人，在可开始状态 |
| 提交 | 真人负责人，执行中 |
| 验收/退回 | 符合验收身份规则且非负责人，待验收状态 |
| 取消 | 创建人或空间管理者，尚未关闭 |
| 转知识/记忆 | 完成后、符合验收身份规则并具备相应资源权限 |

关键写操作锁定父工作行，防止并发破坏状态。退回必须填写原因；活动记录操作者与动作；交付文件和元数据关联保存。删除私有会话不应连带删除已确认工作。

### 9.4 交互

列表首次加载显示整页等待，筛选/刷新保留当前结果。手工新建成功关闭弹窗并刷新列表，不直接跳详情；点击卡片打开独立详情标签。详情标题同步标签，集中显示执行人、验收人、目标、时间、状态、要求、日志和交付物。

### 9.5 Agent 工作建议设计

执行器需要领取、幂等、冻结输入、取消、超时、重试、失败记录、文件交付和用量归因。先试点低风险、只读、交付可核验的场景。执行完成与业务验收通过是两个状态，不能合并。

## 10. 知识库与文档生命周期

### 10.1 组织和权限

支持空间共享与 Agent 独享知识库，共享资源需绑定给 Agent 使用。目录支持层级、根目录、搜索、移动和可读路径。禁止移动到自身或子目录，目标校验归属，同目录同名提示冲突。

目录总数包含所有子目录、不含虚拟根；目录旁文件数为直属数量。停用知识库不参与检索，但管理能力按权限保留。

### 10.2 上传与处理

上传 → 原件保存 → 正文提取/OCR → 摘要 → 分块索引 → 各阶段完成或失败。支持文本创建/编辑、PDF、图片、Office 的处理及预览。

当前单文件上限 500 MB。字节传完、服务端保存成功、后台提取/摘要/索引完成必须分别表达，批量逐项显示失败和重试。

OCR 依赖 Tesseract 等外部程序，Office 转换依赖 LibreOffice。无正文时应说明仅获得文件信息，不把二进制编码或文件名当作已理解内容。

### 10.3 存储和一致性

原件、全文、预览及工作交付物主要在文件系统，数据库存元数据、摘要和检索分块。文件保存失败要回滚；后台处理用独立 session，并在提交可见后启动。

已有文件锁、任务状态和重启恢复，但不是统一持久化队列。备份需覆盖数据库与文件目录，单独恢复数据库无法保证下载和检索可用。

### 10.4 管理能力

有分页预览、原件下载、批量 ZIP、文本编辑、摘要查看/手工编辑/重生成、移动、推送、有效期和重索引。批量下载保留原件，过滤危险路径和处理重名，响应结束清理临时文件。

人工摘要与自动摘要保留来源，失败可理解、可重试。摘要用于定位和概览，不能取代原文事实。

### 10.5 有效期

按上海时区自然日判断，截止当天有效，空值永久。过期/停用内容不进 Agent/RAG；有权用户仍可预览、下载和续期。

### 10.6 检索路径

Agent 常用摘要定位、全文相关窗口及必要时全文扫描；独立 RAG 模块有 BM25、多查询、HyDE、混合和父子块策略。embedding/向量代码存在，实际使用依赖模型、索引及部署。

不能写成向量全部未开发，也不能写成已全面替代 BM25。下一期用统一业务题库比较召回、来源准确性、时延和消耗，再确定统一策略。

## 11. 数据能力与工具

### 11.1 数据接入

支持 PostgreSQL、MySQL、HTTP API；有加密凭证、连接测试、Schema 同步、查询/API 能力、参数和结果 Schema、Agent 绑定及查询记录。

建议流程：数据源 → 连通测试 → Schema → 能力配置 → 参数定义 → 限量试运行 → 保存 → 绑定 Agent。凭证不得出现在普通响应和调试输出中。

### 11.2 SQL 辅助

有原始 SQL、参数化草稿、输入 Schema 生成和未保存草稿试运行。生成不等于保存；字段必须对应 SQL 命名参数；试运行只读、限时、限行。失败分别表达校验和执行原因。

结果区分业务总数、返回行数、截断样本，不能把前 N 行当全量事实。历史结果不能冒充本次实时查询。

### 11.3 联网及其他工具

SearXNG 已接入实际搜索，开发环境记录监听本机 127.0.0.1:8888，有独立服务和运维文档。需 Agent 启用且遵守查询预算，上游失败如实返回。

通用工具模型/API 存在，实际可调用范围仍由绑定与授权决定；注册工具不等于允许任意外部动作。

## 12. 记忆、用量与审计

### 12.1 记忆

支持事实 semantic、事件 episodic、关注 focus，具有提取、保存、管理、检索注入与工作成果沉淀。范围受用户所有权、空间和 Agent 约束。

关注记忆只是后续上下文参考，不创建监控、提醒或定时任务。建议完善来源、时间、冲突、重复合并、失效和删除传播，避免长期积累互相矛盾的信息。

### 12.2 用量

业务操作关联多次模型调用，支持汇总、趋势、分组、明细、调用链和 CSV，覆盖摘要/记忆等辅助调用。页面仅超级管理员可访问。

缺失 Token 与真实零值需区分，未返回用量不代表免费。当前是运行分析，不是费用结算系统。服务器和本地用量来源分类有少量差异，需后续发布对齐。

### 12.3 审计

安全审计覆盖关键身份/授权操作；Work 活动覆盖业务流转。建议统一关联 ID 串起请求、操作、模型、工具和后台任务，解释谁在何时用哪个版本基于哪些来源完成什么。

## 13. UI 与交互规范

### 13.1 布局

左侧栏 + 右侧内容，顶部 44px 页面标签栏，不设全局账号顶栏。账号固定侧栏底部；品牌/空间在顶部，导航独立滚动。页面外层边距由应用框架 page-content 统一提供，页面避免重复 padding。

### 13.2 多标签

同地址重复打开激活已有页，详情独立；浏览器历史同步。切换保留表单、筛选、滚动和进行中的对话，关闭才卸载。各页有独立路由上下文，后台弹窗隐藏；支持方向键、Home/End、Delete。切换账号/空间清空状态。

### 13.3 主题

浅色、深色和跟随系统，默认跟随系统；首次渲染前恢复，减少闪烁。偏好按浏览器中的账号隔离，不代表跨设备同步。

有 165 套纯色、撞色、渐变、玻璃、纹理预设及自定义。使用语义变量，阅读区保持可读，操作和选中态体现主题；不新增固定白底、浅色灰字或固定紫色按钮。

**发现的规范漂移：**旧文档写全透 0px、磨砂 24px；当前 theme.js 的控件/表面/菜单为 clear 14/18/24px、frosted 28/34/38px，另叠加饱和度、对比度和亮度。本轮保留当前视觉实现，测试检查磨砂具有更强模糊语义。具体参数列为实现现状，正式视觉规范待收口。

### 13.4 共享控件

按钮、输入、菜单、卡片、弹窗、表格、标签、进度和空状态复用共享样式。主要操作使用 btn btn-primary，次要操作用已有样式；保留 hover、focus-visible、disabled、只读与错误态，不能仅靠颜色表达。

目录选择复用 SearchSelect，支持完整路径搜索、根目录和非法目标排除；窄屏弹窗和下拉不越界。上传任务显示在工具栏下，compact 不能隐藏整个进度组件。

### 13.5 通用状态

| 状态 | 体验要求 |
| --- | --- |
| 初始加载 | 明确读取中，不展示伪造业务数据 |
| 空结果 | 解释为空原因，提供有权限的下一步 |
| 筛选刷新 | 保留控件和当前结果，完成后更新 |
| 保存中 | 防止重复提交，保留输入 |

| 长任务 | 区分传输、处理、完成，追踪真实状态 |

### 14.3 异步与失败

工作流引擎存在异常生成“模拟回复”的路径，有伪成功风险，应优先改为真实失败、错误原因和可控重试。

## 15. 非功能与发布约束

安全回归覆盖空间、私有所有权、Agent 授权、CSRF、失效、流中撤权、上传和凭证。仓库历史仍存在硬编码连接默认值及运维账密，应另行治理与轮换；本文不复制这些内容。

容量重点是 OCR/Office 转换并发、消息分页、预览按页加载、批量下载临时空间和前端大包。开发服务器历史规格较小，不能把历史性能当最新测量；先建立负载基线再确定 SLO。

开发目录 /opt/agentdevstu，服务 agentdevstu.service，环境文件 /opt/agentdevstu/.env。前端在 frontend/ 构建到后端静态目录，发布采用 rsync 和 systemd，检查服务和页面。

本轮只读核查服务正常；服务器加载的 51 个 ORM 模型对应表/字段未发现缺项。仅为存在性对照，不证明类型、索引、约束、数据或迁移版本完全一致，未执行任何 DDL。

服务器存在本地未包含的少量历史页面和用量分类调整。本轮保留线上差异，仅发布对照确认的知识归档兼容修复。完整发布前需双向归档与基线对齐，避免整目录覆盖。

部署核验：原知识库 API 文件已备份，修复文件与本地 SHA-256 一致；重启后 agentdevstu.service 为 active，首页与登录页 HTTP 均为 200。本轮未覆盖前端产物或服务器独有文件，页面检查仅证明入口可访问，不替代登录后的完整业务验收。

## 17. 下一阶段路线图与验收

以下为依赖顺序建议，不是批准排期或工期承诺。

### 阶段 A：稳定与可追溯

消除假成功，对齐部署，完成独立数据库权限/事务回归，登记凭证与依赖治理，明确版本语义。验收：失败不冒充成功、越权被拒、运行可追溯、发布可回滚。

### 阶段 B：知识与业务数据可信

建立产品/政策/经营数据题库，覆盖同义词、多文档、过期、OCR 无正文、SQL 截断和数据源故障。验收：答案来源可核对，过期/停用不命中，未查询不冒充实时数据，记录质量、延迟和消耗基线。

### 阶段 C：统一工作入口

会议与对话统一进入候选确认，确定 Task 映射，完善分派解释及通知策略。验收：不重复创建、可追溯但不泄露私有来源、真人执行/验收/退回完整通过。

### 阶段 D：可控 Agent 执行

选一个只读且交付可核验场景，交付领取、重试、超时、取消、交付和验收，再扩展可视化工作流及并行/分支语义。验收：重启不重复副作用，取消一致，失败可解释，执行完成与验收分离。

### 待产品决策

1. 已发布 Agent 编辑后何时生效，历史会话如何升级。
2. 会议候选逐项或批量确认，默认验收人规则。
3. 首个 Agent 自动执行场景、允许工具和预算。
4. 通知渠道、触发事件、免打扰；关注记忆与提醒明确分离。
5. 共享知识是否需要审批发布。
6. 记忆自动提取范围、可见性和保留周期。
7. clear 玻璃命名/参数保留现状还是恢复历史设计。
