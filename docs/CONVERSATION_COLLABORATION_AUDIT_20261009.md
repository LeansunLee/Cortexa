# 对话协作与工具调用复核（2026-10-09）

## 范围与验证

复核现有 GoalLoop、LLM/Proxy 协作、普通 Proxy 执行、用户问答续接、原会话恢复、SSE 解析、任务完成检查及来源展示。本轮为审查，没有部署新代码、重发外部任务或修改数据库结构。

最近一轮已部署变更的相关回归为101项通过。本轮另外使用 AsyncMock 模拟普通 Proxy 响应与超时，不连接业务系统，复现下面两个确定缺陷。该回归数不是全仓库或所有执行入口零缺陷证明。

## 已解决

1. 协作授权为空拒绝名单时错误生成“已拒绝”提示；每轮注入当前授权、候选、可执行工具与真实协作结果，历史拒绝不继承。
2. Proxy 子任务传递与参数校验：保留具体拆解任务，显式分工优先；不再静默删除错误协作参数后退回原始大任务；引用真实 observation。
3. 统一 ask_user 决策卡：暂停、单/多选、自由回答、续接原上下文、幂等提交及回答后的恢复链路。
4. 已知超时预算不一致：Proxy 等待尊重配置及共享 Goal 剩余预算，去除原120秒上限。
5. SSE预算：报告与传输事件分开计量，不再把工具遥测和逐字协议开销当成最终报告。
6. SSE错误分层：单个工具失败不终止 Agent；任务级显式失败形成 FAILED observation；未知外部行动不自动重发。
7. 明确缺数时的结束检查：预算内一次纠正，仍不能解决时询问用户；用户接受缺数草案可交付。
8. Knowledge相关性：实体约束、证据等级、Top K不凑数、证据不足与上下文注入跟踪。
9. Memory来源：保留标识、按权限读取详情、恢复可核实的历史引用；撤回/归档来源不泄露旧正文。
10. 可观测性：主流程内草稿、目标、来源、Agent用量和Prompt查看，保留调试权限隔离。
11. UI和字段：工作规则字段合并、Proxy协作来源设置简化、新建对话交互、输入区尺寸及玻璃浮层可读性调整。

## 仍存在的问题（按优先级）

### P1 普通 Proxy 执行与 Goal 路径不一致（确定、已复现）

位置：`src/cortexa/agents/proxy_executor.py:357`。

- 模拟外部 JSON `{"ok":false,"status":"failed"}` 后，`execute_proxy_agent` 返回 `success=True` 并走completed审计路径。该路径未统一检查任务终态。
- 模拟 `httpx.ReadTimeout` 后，在 `except UserQuestionPause` 处触发 `UnboundLocalError`。该类只有在函数内某个条件分支 import 后才初始化，异常可以先发生。
- 该入口仍有宽泛异常重试循环。修复变量引用时，也必须把结果未知的请求从自动重发中排除；不能只让旧重试循环重新生效。
- 普通调用和普通 Proxy 问答续接未传入 `max_response_bytes`，与 Goal 入口的有界增量读取不同。

建议复用同一个结果分类器和传输策略，区分成功、等待用户、明确失败、拒绝请求、结果未知，禁止未知执行盲目重发。

### P1 通用原会话恢复入口不完整（代码确认，最近两轮实际依赖维护脚本）

位置：`src/cortexa/api/user_questions.py:545` 与 `:553`。

当前 recover 接口要求提问者本身是 Proxy，并要求decision_continuation与continuation检查点。首次协作断流没有这些字段；主LLM提问之后的Proxy协作中断，提问者也不是Proxy。即使已有remote_execution.session_id，用户仍不能通过该接口取回结果。

`pending_question` 又可能对Goal中断统一显示can_recover，导致UI提供的能力与实际接口条件不一致。

建议从当前未确认 action 定位真实目标 Agent，利用remote_execution作只读核实，覆盖首次协作与问答续接。必须验证权限、契约、原任务/回答身份、完整终态以及报告预算；结果未完成时仅等待，不重发POST。

### P2 初次 Goal 执行与问答续接的断线行为不同（代码确认）

位置：`src/cortexa/api/goals.py:661`。

首次Goal SSE生成器退出会cancel worker；回答决策卡则有detached worker。浏览器刷新/网络掉线可能取消本地主流程，远端继续运行，随后产生结果未知。不能把网络断线与用户主动停止当成同一语义。

建议复用现有受预算和授权监控的任务worker；断线只脱离观察，用户明确停止用独立控制动作。与通用结果恢复一起处理。

### P2 任务完成检查仍是保守文本检查（代码确认）

位置：`src/cortexa/runtime/completion.py:37`。

- 缺数检查依赖“数据/销量/基数/明细”和“未取得/仍缺”等表达；模型没说缺什么或换一种表达，仍可能漏检。
- 拒绝矛盾检查目前只在整个denied_agents为空时触发。若确实拒绝了A，模型错误地声称可用的B被拒绝，该检查可能漏掉。
- 这不是完整的语义任务验收，也不是保证所有必要取数都执行。

建议保持模型自主拆解，补充结构化完成依据及逐Agent状态核对；不硬编码销售部门或车型。
