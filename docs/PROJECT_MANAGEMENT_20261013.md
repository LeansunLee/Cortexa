# 项目管理第一版

## 范围

项目 → 工作 → 原有交付物。项目有目标、范围、负责人、成员、截止时间及 planned / active / completed / archived 状态。完成需负责人手动确认；进度只汇总当前用户可见工作，不自动改变项目状态。

项目详情包括概览、工作、成果和动态。工作可不属于项目，最多属于一个项目。关联、移出不重置原执行状态、负责人或验收人。归档禁止新增或移入，允许移出和继续处理已有工作。

对话输入框通过引用项目按钮或 `#项目名称` 搜索，按 ID 引用最多三个项目；默认只在本轮生效。项目详情可进入对话并预选项目。从回复创建工作时，单项目引用预选归属，多项目需手动选择。

## 权限与运行时

- 同一工作空间内，创建人、负责人、成员、空间管理员可读项目；创建人、负责人、空间管理员可管理项目。成员不自动取得所有工作的访问权。
- 项目统计、成果和动态均过滤工作可见性，不暴露不可见工作的标题、数量或交付物。
- 原有工作创建人或空间管理员可变更工作归属。
- 主 LLM、协作 LLM、普通 Proxy、目标协作 Proxy、用户回答续执行使用有权查看的项目摘要。GoalLoop 每轮重新检查项目权限；按需读取工具每次检查 Agent 与项目/工作权限。
- `project_read` 是只读工具，仅允许本轮明确引用的项目，返回最多50项可见工作或单项工作及交付摘要。初始摘要最多20项，受 Context Budget 限制。大型输出提示分项读取，不重新查询业务数据、不把未验收成果当作事实、不发送完整项目历史。
- 复用来源引用、Prompt、工具 Observation、Runtime Trace 和预算控制，不引入第二套执行引擎。项目引用不是修改项目或自动派发工作的授权。

## 已确认的 Schema 变更

用户确认方案后实施 migrations/add_projects_20261013.sql：新增 t_projects、t_project_members、t_project_activities；t_works 增加可空 project_id。复合外键保证工作与项目同工作空间。历史工作保持 NULL，不推断归属。

迁移以一个事务执行，lock_timeout 5秒，失败全部回滚。部署前备份应用代码与全库 custom-format dump。先迁移后部署，旧代码兼容新增表/列。

回滚优先恢复应用代码和前端，保留新增数据表及列，防止丢失已经建立的项目。仅在明确决定丢弃项目数据并另行确认后，才执行删除表/列或整库还原。

## 验证

- 隔离真实 PostgreSQL：创建项目、成员权限、隐藏工作/成果隔离、工作关联与移出保持状态、归档限制、摘要预算、只读工具、Goal 项目来源与提示词、兼容迁移保留历史工作。
- 浏览器（模拟 API，真实构建）：项目创建、关联/移出、对话预选引用、每轮引用清理、桌面与窄屏布局。
- 原工作、对话、Goal 协作、Proxy 和用户决策回归。

## 后续范围

第一版不包括里程碑、甘特图、工作依赖、自动项目调度、项目自身附件库、对话永久绑定项目。交付物沿用工作验收与下载规则；项目状态由用户手动确认。
