# Proxy 协作子任务传递修复（2026-10-08）

## 原因

销售部已将销售目标拆解为销量、销售额、目标达成、车型结构、区域排名和库存等数据需求，
但使用了外部请求字段 `input`。协作调用 Schema 原先仅接受 `task_fields`、`observation_bindings`，
参数修复删除未知字段后产生空调用，平台继而使用原始用户目标，丢失拆解内容。

## 修改

- Proxy 协作调用新增 `task`（非空文本，最多 8000 字符）：只承载具体子任务指令。
- `task_fields` 指定指令对应的文本字段；唯一兼容字段可自动选择。
- 优先级为用户显式字段、指定的已有结果绑定、用户明确分工/Agent 子任务/原始任务。
- 不接受模型直接填写任意外部业务字段；观察结果引用、字段投影和最终请求预算仍生效。
- 投影记录区分 `delegated_task` 和 `goal_task`；协作审计记录实际子任务摘要。
- 目标输入契约与协作调用参数明确区分，提示 Agent 先拆解数据需求。
- Agent 调用参数校验失败时不删除字段：返回调用 Schema，消耗共享重规划预算自行修正。
  无修正预算时以 `invalid_collaboration_arguments` 停止，未派发外部请求。
- 不修改数据库表结构，不重放历史外部请求。

## 验证

使用实际销售部错误参数回归：首次调用被拒绝，修正为 `task` 后只派发一次，
外部 `prompt` 收到完整拆解内容。验证用户参数/分工优先、已有结果引用、禁止直接填写
结构化事实、文本限长与预算，以及决策卡片暂停、回答、断线和原会话恢复路径。
