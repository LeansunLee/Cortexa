## 二、产品定位

Cortexa 是一个 **AI 智能体管理平台**，用于创建、配置、管理和运行 AI 智能体。智能体代表公司部门、职能角色或某种职业，具有明确的人格、职责、能力边界和输入输出接口。平台支持多工作空间隔离与组织 / 角色权限体系，支持知识库、数据源、目标运行时、多智能体协作，以及围绕「对话 → 工作 → 项目」的执行主线与记忆治理。

**核心价值主张**：让企业快速构建领域专家型 AI Agent，通过知识库和数据源赋予真实业务能力，通过对话目标运行时把一句话任务变成可观测、可协作、可交付的工作成果，并通过会议系统和记忆系统沉淀组织知识。

## 四、核心产品逻辑

### 4.1 智能体（Agent）

**生命周期**：创建 → 配置 → 保存草稿 → 测试 → 创建版本 → 发布（需业务角色非空）→ 对话 / 被调用；发布后状态 `active`，会话要求 `active` 智能体。

**配置维度**（编辑器 Tab）：基础信息（头像上传裁剪 + 17 个多元预设 SVG）、身份与业务角色 / 职责（运行时采用业务角色字段）、工作边界、Proxy 配置、Schema（JSON Schema + CodeMirror）、模型、版本、知识库、数据能力、记忆。字段带 **LLM 上下文标记**（哪些字段会进入模型提示词），协作上下文字段有协作指示。

**智能体类型**：LLM 智能体（System Prompt 从配置字段自动拼接 + 知识 / 数据 / 记忆注入）；Proxy 代理（转发外部系统 API，字段映射，目标协作 Proxy 由运行时投影调用）。

### 4.2 目标运行时（Goal Runtime）

聊天发送先经 **message-route** 判定：普通闲聊 / 附件 / Proxy 主 Agent / 功能关闭 → 既有普通对话流；判定为 Goal → `POST goals/stream`：

```
解析 Goal → 解析参与者 → 计算有效策略与预算
  → 缺关键信息：WAITING，ask_user 向用户澄清（推荐选项、超时自动继续）
  → 否则幂等创建 Goal → SSE 执行器（重验权限与策略）→ 装载数据/Web/知识/记忆/Agent 能力
  → GoalLoop 有界循环：模型流式推理 → 文本形成最终回复 / tool call 整批校验（结构/工具名/参数/权限/风险/预算）
  → 允许的调用先持久化 Action=started 再执行 → Observation 持久化 → 有上限的模型可见投影 → 下一轮
  → 结束：保存结果、状态、来源、协作记录、调试轨迹 → SSE done/status/error
```

预算分阶段（NORMAL / CONSERVE / FINALIZING / EXHAUSTED）：web_calls 耗尽进入收尾合成（汇总已收集来源），仅核心预算（时长 / LLM 调用 / 输出 token / 步数）触发 EXHAUSTED 停止。断线后可恢复与对账；前端以 `RuntimeTimeline` 呈现执行过程，调试账号可看分支与上下文。

### 4.3 工作系统（Works）

```
创建（可从对话候选一键转工作）→ 派发 → 开始 → 提交交付 → 验收通过 / 退回修改 → 完成
                                                        ↘ 取消 → 删除（仅已取消，创建人/空间管理员）
```

- 交付物上传下载沿用验收规则；工作日志记录执行过程；可沉淀到知识库或 Agent 记忆
- 对话自动提取工作候选（LLM 抽取，骨架屏过渡）；候选可提议为工作，关联工作被删除后回到可提议态
- 对话可引用工作（≤5 个）：`work_read` 工具按轮校验权限，会话工作摘要注入上下文，来源引用展示
- 推荐负责人自动填充；工作与来源会话双向关联；验收人不能与负责人相同

### 4.4 项目管理（Projects）

项目 → 工作两级：项目有目标、范围、负责人、成员、截止时间与 planned / active / completed / archived 状态；工作最多属于一个项目，关联 / 移出不重置执行状态。完成需负责人手动确认；进度只汇总当前用户可见工作。项目详情（概览 / 工作 / 成果 / 动态）全部按工作可见性过滤。对话引用项目（≤3 个，默认仅本轮生效）：`project_read` 只读工具按轮检查 Agent 与项目权限，GoalLoop 每轮复查。归档项目禁止新增 / 移入工作，可移出并继续处理已有工作。

### 4.5 记忆系统 2.0（Memory 2.0）

- **摄入治理**：Agent 记忆摄入经 LLM 判定动作（新建 / 合并 / 冲突 / 时间线更新），带证据（`t_memory_evidences`）、置信度依据、敏感与高风险处理；显式用户纠正（`source_mode=explicit`）在冲突 / 时间线二义时**直接替代旧记忆**（旧记忆退休，不生成冲突对）
- **召回**：策略化检索（policy version memory2.1）：相关度阈值、时间窗、term/时间/ token 估算、过滤原因可解释；对话 / 目标运行时均可检索注入
- **治理界面**：Agent 运维 → 记忆：弹窗操作、筛选、问题（issues）、关系、事件与来源详情

### 4.6 知识库（Knowledge Base）

- 两级体系：空间共享（`agent_id=null`）+ Agent 独享；支持文件夹（`t_knowledge_folders`）
- 存储：DB `content` 列只存摘要（≤2000 字符），全文存文件系统 `data/documents/{doc_id}/content.txt`
- 检索：两段式（先摘要定位文档，再全文窗口提取，无命中回退全文扫描）；BM25 + jieba；超时保护不阻塞对话；过期文档保留文件但所有检索路径排除
- 抽取状态机：`extraction_status` = ready / unsupported / error；无文字的有效文件生成「文件信息摘要」并标记 unsupported（终态不索引）；失败原因按文件类型给用户可读文案，原始异常存 `extraction_error_detail`；编辑 / 摘要 / 索引后台任务用 `content_revision` / `summary_revision` 乐观校验，文档删除时清理任务锁并防孤儿锁

### 4.7 对话系统（Chat）

- SSE 流式（独立 DB session + LangChain `astream`）；历史消息限制轮数
- 执行路径二分：普通对话流 vs Goal Runtime（见 4.2）
- 答案来源：内联来源 pill（悬停预览、去重折叠），覆盖知识库 / 数据源 / 项目引用
- 会话工件：`save_document` 保存产物，面板查看 / 编辑 / 下载
- 引用体系：「+」添加菜单统一附件 / 引用项目（≤3）/ 引用工作（≤5）；已取消工作与归档项目不在菜单展示
- 对话调试（按账号开关）、重命名、重新生成、搜索、加载骨架

### 4.8 会议系统（AI Meeting）

创建会议（选择参与者与主持人、设定轮数、会议目的必填、附件注入提示词）→ 多轮讨论 SSE 实时推送 → 主持人总结 + 冲突检测 → TodoList 生成。

### 4.9 登录与权限

登录页 + 登录会话（`t_login_sessions`）；用户 / 系统角色 / 身份提供商 / 外部身份；工作空间成员角色与档案；Agent 授权（`t_agent_grants`）；安全审计日志。前端 `can()/canAdmin()` 控制路由与按钮；数据可见性（项目 / 工作）在 API 与运行时双层校验。

### 4.10 工作空间（Workspace）

资源隔离的组织单元：独立管理 Agent、知识库、工作、项目、数据源；工作空间默认模型；侧栏工作空间切换器（折叠时隐藏）。

## 五、性能优化经验

### 5.1 服务器资源管理

2 核 1.7GB 服务器：Uvicorn 并发限制（`--limit-concurrency 50 --timeout-keep-alive 30 --backlog 64`）、大文本存文件系统、systemd 管理；服务器内存吃紧时前端构建放本地（服务器构建有 OOM 风险）。

### 5.2 SQLAlchemy 异步会话陷阱

SSE StreamingResponse 中不能使用 request-scoped session（generator 在请求结束后才执行）——流式端点在 generator 内部创建独立 session（`async with async_session_factory() as db`），Goal Runtime 同理。

### 5.3 Vue 3 响应式陷阱

操作 ref 数组必须通过 `.value`（Vue 代理对象），直接改原始数组不触发更新。

### 5.4 SSE 流式输出实现要点

后端 `astream` 逐 token yield；前端 `fetch` + ReadableStream + TextDecoder 解析；`streamContent` ref 实时追加；知识检索 `asyncio.wait_for` 超时保护。

## 六、UI/UX 设计经验

- **玻璃材质体系**：液态 / 磨砂 / 通透三种材质，覆盖对话框、浮层、下拉、开关、单选；通透对话框中心保持半透明 + 液态边框光；规范见 `docs/UI_LAYOUT_GUIDELINES.md`
- **backdrop url() 不可靠**：`backdrop-filter: url(#svg)` 在 Chromium 真实页面静默失败，玻璃质感只依赖原生 `blur()`；浮层穿透用「增强模糊 + 适度底色透明度」解决，不能提高不透明度
- **页内 Tab 规范**：复用公共 `.tabs/.tab`（下划线样式），视觉规范是 Personalization「应用效果预览」demo，不是 pill/segment
- **主题系统**：主题色 / 材质 / 纹理 / 光晕全语义变量（`--surface/--text/--primary/...`），卡片类 UI 禁止硬编码浅色；12 种预设车漆色；悬浮机器人随主题重着色（3-stop 亮度斜坡 + 材质适配）
- **图标规范**：Lucide 统一，禁用 emoji；头像上传裁剪 + 17 个多元预设 SVG 主题自适应
- **布局规范**：无全局顶栏，账号固定侧栏底部，页面边距由应用框架统一提供；侧栏可折叠（图标态隐藏 logo / 工作空间选择器）
- **机器人挂件**：2D 分层美术（`base.png` + 像素表情画布），美术更新必须 bump `ROBOT_ART_VERSION`（浏览器对稳定 URL 的图片启发式缓存数小时，否则用户看到旧图配新几何的错位组合）；`--robot-size` 桌面 190px 已定稿

## 十、关键经验总结

### 架构层面
1. **存储分离**：大文本存文件系统，DB 只存元数据和摘要——小内存服务器的关键优化
2. **摘要即检索索引**：LLM 摘要放后台任务（10-20 秒不能阻塞上传），检索先摘要定位、后全文取窗口；后台任务用修订号乐观校验防旧覆新
3. **异步会话隔离**：SSE / Streaming / Goal Runtime 必须独立 DB session
4. **运行时投影**：工具 Observation 先完整持久化，再投影有大小上限的模型可见结果——调试与上下文控制两全
5. **预算分阶段**：外围预算耗尽进收尾合成而非硬停，只有核心预算才 EXHAUSTED——避免「白跑一场零输出」

### 产品层面
6. **显式纠正 > 冲突对**：用户亲口纠正的记忆直接替代旧值，不要让 Agent 在「用户说的」和「记的」之间摇摆
7. **失败文案分类**：面向用户的原因按文件类型 / 场景给可读文案，原始异常另存 detail 字段
8. **预设 > 手动**；流式 > 等待；来源追踪增加信任感

### 开发层面
9. **Vue ref 必须 `.value`**；LLM 流式用 LangChain `astream`
10. **增量部署**：rsync + hash 校验用 git blob（本机 CRLF 污染工作树文件哈希）；WSL rsync 必带 `-o StrictHostKeyChecking=accept-new`
11. **backdrop url() 不可靠**（见第六节）
12. **scoped 样式回归测试**：Vue scoped 编译产物带 `data-v-xxx` 且构建 hash 变化，静态复现需动态提取 hash 注入或剥除属性选择器
13. **Windows pytest 有红色基线**：9 个模块 fcntl 不可收集 + 若干 POSIX 权限失败是环境性的；判定回归用 `git stash` 前后 FAILED 列表对比，不数数量
14. **合并后先冒烟聊天流**：01969cd 合并曾因 `sources` 初始化顺序让每次发送都 UnboundLocalError——拉取远程提交后先跑一次对话再交给用户
15. **Rolldown (Vite 8) 动态导入解构 minifier bug**：`const {X} = await import('m'); new X()` 会被错缩到 ReferenceError（构建成功、运行时报错）——保留模块命名空间 `new m.X()`
16. **Playwright 陷阱**：未处理的 `filechooser` 事件是模态态，先 `await fc.setFiles([])`；inline `node -e` 后台运行会静默挂起，用脚本文件前台跑
17. **美术资源缓存**：稳定 URL 的图片更新必须带版本参数（机器人挂件 `ROBOT_ART_VERSION`），否则用户看到旧图新几何
