# 对话协作方式（2026-09-28）

对话输入区提供「不主动、询问、主动」三种选择，新对话及未设置过的历史对话默认不主动。

| 工作空间允许的最高协作方式 | 对话可选范围 |
| --- | --- |
| 不主动 | 不主动 |
| 询问 | 不主动、询问 |
| 主动 | 不主动、询问、主动 |

- 不主动：仅用户明确 @ 的 Agent 可参与，不发现或自行调用其他 Agent。
- 询问：需要额外 Agent 时暂停并展示授权面板，用户选择允许的参与者后继续；用户明确 @ 的参与者无需重复确认。
- 主动：Agent 在权限与预算内自行决定协作。
- 平台、Agent 自身的限制仍可进一步收紧范围；工作空间收紧配置后，下次读取选项及执行时重新校验。运行中的单轮任务不会因配置放宽而自动获得更高协作权限。
- 选择保存在已有 `t_conversations.metadata_json.collaboration_mode`，不新增表或字段。选择按对话隔离，刷新后保留，保存失败时显示错误并重新读取有效设置。
- 附件消息仍走现有普通消息流程，仅执行用户明确 @ 的协作；输入区对此显示提示。Proxy 主 Agent 仍走普通对话，不展示自主协作选择。

接口：`GET /api/conversations/{id}/goal-options` 返回有效选择与允许范围；`PUT /api/conversations/{id}/collaboration-mode` 保存选择，校验对话所有权、Agent 使用权限与允许范围。普通对话用户不需要工作空间管理权限。

验证：64 项后端测试通过（本机隔离 PostgreSQL、脚本化模型），覆盖默认值、保存、所有权、工作空间/平台/Agent 上限、三种方式授权、工作空间收紧、确认与续跑。浏览器测试使用真实构建产物与隔离 API 响应，覆盖选项、失败回显、刷新、对话隔离、范围变化和深浅色窄屏布局。
